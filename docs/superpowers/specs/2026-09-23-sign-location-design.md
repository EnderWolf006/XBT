# 签到地点管理与高德候选确认设计

日期：2026-09-23

## 1. 背景与目标

现有项目已经支持学习通位置签到（`sign_type=4`），但缺少可管理的签到地点坐标。本功能为华北水利水电大学江淮校区教学楼增加地点管理能力：管理员可通过高德 POI 搜索生成候选地点，确认后启用；用户在 Web 或 Android 签到时选择一个启用地点，后端将该地点坐标发送给学习通。

## 2. 已确认需求

- Web 和 Android 同步支持。
- 用户签到时选择一个地点。
- 后端根据地点 ID 查询坐标并发送给学习通。
- 地点范围是华北水利水电大学江淮校区教学楼。
- 先由高德 POI 自动搜索候选，再由管理员确认后启用。
- 支持管理员手动输入关键词补充搜索。
- 管理员可以新增、编辑、启用、停用和删除地点。
- 地点保存到数据库，同时支持配置文件或初始化脚本批量导入。
- 不校验用户与地点的距离。
- 高德 API Key 仅保存在后端配置中，不暴露给 Web 或 Android。
- 不未经确认预置无法核实的教学楼坐标。

## 3. 方案

采用“后端高德 POI 搜索 + 候选待确认 + 数据库存储 + Web/Android 选择地点”的方案。

### 3.1 高德候选流程

2026-09-25 调整：后端将已配置校区文字和“教学楼”等建筑关键词组合检索，不将校园地址误作高德 `city`，也不把文本检索声称为地理围栏。管理员可以切换为完整学校/建筑名称检索，不追加校区。单次最多 25 条，结果是否为目标楼栋必须人工核对。

搜索只返回名称、地址、坐标和 POI ID，不写数据库。Web 在独立候选区显示，仅保留本次结果；新请求、空结果及错误都清除旧结果，晚到响应不能覆盖新查询。管理员明确选择某项保存后才新增 `pending`，仍需另行明确启用。已有历史地点不删除，重复保存保护管理员修改和启停状态，不自动恢复已删地点；后续新增显式确认恢复旧ID为pending的独立操作，保留旧字段。保存/恢复后定位、高亮对应管理记录。

高德 Key 配置在 Server 配置或永久配置目录中，例如：

```yaml
amap:
  api_key: ""
  campus_address: "河南省信阳市罗山县龙池大道236号"
```

### 3.2 地点数据模型

新增 `sign_locations` 表，包含：

- `id`
- `name`
- `address`
- `latitude`
- `longitude`
- `amap_poi_id`
- `status`：`pending`、`enabled`、`disabled`
- `source`：`amap`、`manual`、`config`
- `created_at`
- `updated_at`
- `deleted_at`

删除使用软删除，避免历史记录引用失效。应根据高德 POI ID 或名称、坐标组合避免重复导入。

## 4. 接口设计

### 4.1 管理员接口

- `GET /api/admin/sign-locations`：地点列表，可按状态筛选。
- `POST /api/admin/sign-locations/search`：只读高德 POI 搜索，返回无数据库 ID 的临时候选。
- `POST /api/admin/sign-locations/candidates`：明确确认某个候选，幂等保存为待确认或返回已有记录；遇已删地点返回结构化409，不自动恢复。
- `POST /api/admin/sign-locations/:id/restore`：管理员真实确认后恢复该旧ID为pending，保留管理员旧字段；重复/并发幂等，唯一冲突回滚，不自动启用。
- `POST /api/admin/sign-locations`：手动新增地点，行为保持。
- `PUT /api/admin/sign-locations/:id`：编辑名称、地址、经纬度和状态。
- `POST /api/admin/sign-locations/:id/enable`：确认并启用。
- `POST /api/admin/sign-locations/:id/disable`：停用。
- `DELETE /api/admin/sign-locations/:id`：软删除。

上述管理员接口必须进行管理员权限校验。

### 4.2 用户接口

- `GET /api/sign/locations`：只返回已启用且未删除的地点。
- 现有签到请求 JSON 顶层增加正整数 `location_id`（不放入 `special_params`）；后端根据该 ID 查询地点坐标，不接受客户端直接决定最终坐标。

地点不存在、已停用或已删除时，后端拒绝签到并返回明确错误。

## 5. 客户端设计

### 5.1 Web 管理端

新增签到地点管理页面，支持状态筛选、自动搜索教学楼、自定义关键词搜索、候选确认、编辑、启停、软删除和手动新增。候选结果默认不启用，高德调用失败、无结果和重复地点均显示明确提示。

### 5.2 Web 与 Android 用户端

签到页面加载启用地点列表。用户必须先选择地点再提交签到；列表显示地点名称和地址。没有可用地点时显示提示。Web 和 Android 使用同一后端接口和顶层 `location_id`。2026-09-24 核实的公开 Android 实现为 WebView + CameraX 壳，加载共享 Web 页面，而非独立 Kotlin 地点业务。

## 6. 签到数据流

1. 客户端请求启用地点列表。
2. 用户选择一个地点。
3. 客户端在签到请求 JSON 顶层提交 `location_id`，位置类型的客户端 `special_params` 不包含坐标。
4. 后端验证地点存在、已启用且未删除。
5. 后端读取数据库中的纬度和经度。
6. 后端将坐标组装进学习通位置签到请求。
7. 返回原有签到结果。

不增加距离校验，不改变其他签到类型的现有流程。

## 7. 错误处理与安全

- 高德 API Key 缺失或无效：管理员搜索接口返回配置错误，不影响已有地点签到。
- 高德配额或网络失败：返回可理解的失败信息，不能创建不完整地点。
- 高德无结果：返回空候选列表和提示。
- 坐标超出经纬度合法范围：拒绝保存。
- 重复 POI：提示已存在，不重复启用。
- 非管理员访问管理接口：拒绝访问。
- 客户端不能直接覆盖后端最终使用的坐标。
- 高德 API Key 不进入前端构建产物和 Android 包。

## 8. 配置导入

提供配置或初始化脚本的批量导入方式。导入数据进入同一 `sign_locations` 表，并标记 `source=config`。导入应支持幂等执行，不覆盖已由管理员修改的地点；重复项按高德 POI ID 或稳定的名称、地址、坐标组合识别。

## 9. 测试与验收

后端测试覆盖：地点 CRUD、状态转换、软删除、管理员权限、坐标校验、重复导入、配置导入、高德响应解析、API Key 缺失/失败、`location_id` 到坐标的签到请求映射。

Web 测试覆盖：候选搜索、待确认列表、确认启用、编辑、停用、删除、地点选择和缺少地点时的提示。

Android 测试覆盖：地点列表加载、地点选择、`location_id` 提交、停用地点错误处理。

验收标准：

1. 管理员能够搜索并看到高德教学楼候选。
2. 候选在管理员确认前不能用于签到。
3. 管理员确认后，Web 和 Android 均能看到启用地点。
4. 用户选择地点后，后端使用该地点数据库坐标发起位置签到。
5. 客户端不能通过修改请求坐标绕过地点选择。
6. 地点停用或删除后不能继续用于签到。
7. 高德 Key 不出现在 Web 或 Android 构建产物中。
8. 既有非位置签到流程不受影响。

## 10. 范围外事项

- 不自动确认全部高德候选地点。
- 不在本阶段提供地图可视化选点器。
- 不进行用户与地点的距离校验。
- 不改变学习通其他签到类型。
- 不删除永久数据目录 `C:\Users\user\AppData\Local\XBT`。
